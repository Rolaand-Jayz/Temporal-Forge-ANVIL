**Changed behavior / repair:** two root causes, both repaired. (1) The warning banner `Rectangle` in `resources/qml/SettingsDialog.qml` was a `ColumnLayout` child sized by a plain `width: parent.width` binding, which the layout does not honor — the banner rendered zero-width/misplaced and its centered text overflowed left across the 181px sidebar divider, cutting each line's lead-in. Now `Layout.fillWidth` + adaptive `Layout.preferredHeight`, both lines width-capped with word-wrap fallback, `objectName`s for bounds checks. (2) On KDE Wayland a client resize issued while the window is still inactive — the state right after the modal Settings dialog hides — is silently dropped by the platform (reproduced in a two-window probe: `docs/review-handoffs/pr-8/2026-10-14_repair-cbcd8101/resize-rootcause-probe/`), so the prior test snapshotted the stale 760×480 layout for both width cases. `tests/native_player_ui_tests.cpp` now activates the window, re-issues the resize across transient compositor states, asserts the **delivered** geometry (fails loudly otherwise), logs realized logical size + DPR, resizes the Settings dialog itself to confirmed 760/1280, asserts the two player captures are distinct layouts, and checks the warning banner is visible, inside the content viewport, and untruncated at both widths.
